# M2 CRM vertical report

M2 is accepted. This milestone deliberately combined the CRM parts of the original platform, adapter, module and UI milestones into one local vertical slice. The result is a usable CRM backed by Payload and D1, with domain rules, access control, deterministic seed data and product pages connected end to end.

## Delivered

- CRM contracts, money values, repository ports, collection slugs, field constants, staff scopes and navigation.
- Organizations, contacts, leads, deals, sources, lost reasons and stage-transition collections, plus the M2 migration.
- A Payload CRM repository with typed mapping, compare-and-set updates and stage-transition history.
- Domain commands for create, update, stage movement, lost outcomes and idempotent lead conversion.
- Shared stage, record, activity, confirmation, form and filtering UI composites.
- Lead table, board, record, create, conversion and lost flows.
- Deal table, board with value totals, record, won and lost flows.
- Organization and contact tables, records, create and edit flows with their relationships.
- Deterministic local CRM fixtures and a root `pnpm dev` command that loads the local vars without a manual export.

## Acceptance evidence

- `pnpm verify` passed on the integrated branch.
- Unit suite: 67 files and 605 tests passed.
- Local Payload and D1 integration suite: 17 tests passed, including migrations and concurrent-write protection.
- Harness evals: 6 targets and 0 failures.
- Dependency analysis: 375 modules and 928 dependencies, with no violations.
- Typecheck, lint, formatting, unused-code analysis, duplication threshold, vocabulary, branding, disable checks and documentation checks passed.
- The production build emitted every CRM table, board, record, create and edit route.
- The server bundle size check passed at 2,327 bytes.

## Browser acceptance

The lead reset and seeded the local database, then started the application with plain `pnpm dev`. The authenticated in-app browser showed 3 active leads, 5 deals, stage value totals on the deal board, 3 organizations and 6 contacts. Leads, the deal board, organizations and contacts each returned 200. Browser warnings, browser errors and server warnings were empty.

## Harness outcome

M2 produced a 4 of 10 first-pass rate, 18 retries and no promotion candidates. The repeated findings activated lessons and executable evals for access scope, contract drift, edge cases, gate failures and scope violations. The six eval targets pass in both reproduction and fixed modes.

The raw M2-W5 attempt 2 record reports one lead takeover. That is preserved append-only telemetry, but the W5 report explains that the attempt was run by a worker and was recorded with the wrong runner. Attempt 3 corrected the metadata. No implementation worker was replaced by the lead.

The closed loop changed the product and the harness together. Dependency cycles led to shared-type boundaries, unused exports led to executable checks, a stale seed expectation became an integration regression, invalid directory link semantics gained a focused regression, and the plain development entrypoint gained deterministic environment tests.

## Known limitation

Vitest 4.1.11 and its V8 coverage remapper emit nonfatal parser warnings for some TSX files and exclude those files from coverage. The unit tests still pass and the affected UI was exercised in the browser, but the reported coverage percentage does not measure all rendered components. A later test-infrastructure milestone should add component-browser coverage or replace the failing remap path.

## Decision

GO. The M2 CRM slice is complete and locally demoable. Cloudflare deployment, the remaining product verticals, broader browser automation and production onboarding remain outside this milestone.
