## How the reference check was done

Three research passes read the reference code in `/references` (Twenty and Frappe CRM mainly) for each row and compared it with the tested behavior above. Where a reference has no matching feature, or the row is Mirch-specific, the cell says so. Gaps found were fixed where the row's contract needed them: invitation hint on sign-in (01), copy link in the command menu (03), Today on the calendar (25), search kept between deal table and board (17), mixed currencies no longer added together on the deal board (24), and a note that problem rows are skipped on import (47). Reference features Mirch does not offer, such as column move and resize (14), operator choice per filter (15), aggregate choice (24), week view and drag in the calendar (25), a call log (28), and inline edit in the import preview (47), are listed in the cells; the row contracts say 'where offered', so they are not required for acceptance.

A hand-driven pass in the real Chrome browser (signed in as the seeded test owner on the local app) covered: the sign-in hint, the lead filter chips and Clear all, the task side panel with the unsaved-description prompt, and a 390 px layout check of 23 pages in a 390 px wide frame inside Chrome. A second pass used a real Chrome window narrowed to its smallest allowed width (a 406 px viewport; Chrome will not go below that on this machine): sign-in page, dashboard, lead filters with Clear all, tasks list, and the task panel with the unsaved-description prompt all work in the phone layout, with no sideways scroll and no cut-off header control. It found one defect the automated tests had missed: the Table / Board / Follow-ups switcher was cut off at the right edge of the phone layout. The page header now wraps its actions (v0.9.62), and `parity-shell.spec.ts` now fails if any header control runs past the screen edge.

Automated tests run in Chromium (desktop) and in WebKit with an iPhone 13 profile at 390 px, the browsers Playwright drives. They do not run on physical phones.
