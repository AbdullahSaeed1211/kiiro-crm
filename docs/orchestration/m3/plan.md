# M3 completion wave plan

M2 proved the CRM vertical and closed on `main`. This plan replaces the remaining provisional M3 through M7 decomposition with five larger, independently reviewable verticals. Each worker owns one product outcome, its tests, documentation, attempt telemetry and report. Shared assembly, migrations, end-to-end acceptance, authenticated Cloudflare actions and final milestone reports remain lead-owned.

All workers start from the M2 completion commit on `main`, work in isolated worktrees and use the repository agent protocol. They must not inspect another active worker, must not contact Cloudflare or other authenticated services, and must send one completion notification after pushing a clean branch. Every remediation and every `fix(...)` commit uses the next append-only attempt and records the harness finding, countermeasure and evidence.

## Integration boundaries

- Workers add leaf collection, repository, hook and UI modules. They do not edit Payload registration, generated Payload types, migrations, central seed assembly or central package barrels. Their reports list every lead assembly step required.
- M3-L1 owns the tenant schema, Wrangler generators and generated mail-router configuration, and the deploy workflow. M3-W5 supplies the noncritical operations implementation and records the required lead-owned diffs in its handoff.
- M3-W3 owns the `savedViews` and `layouts` collection definitions, access rules and repositories. M3-W1 owns the settings pages that administer shared views and records the W3 service boundary as an integration dependency. No second collection definition is accepted.
- A worker may refine an existing file only when it is named in that worker's exclusive scope. If the current architecture makes a shared edit unavoidable, the worker records a dependency request and stops that portion without widening scope.
- Each vertical must be coherent enough to review as a product outcome. Small internal tasks stay inside the worker and do not become separate sidebar tasks.

## Completion boundary

This wave completes all code and local evidence through the original M7 scope. M8 needs the platform and customer prerequisites in spec §20, customer data, external site access and authenticated deployment. M9 needs pilot-week feedback. The lead prepares those paths but does not invent customer inputs or production evidence.
