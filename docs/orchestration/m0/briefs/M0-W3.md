# Brief: M0-W3 — Core harness scripts

- **Milestone:** M0 · **Attempt:** 1 · **Branch:** `wp/M0-W3` from `m0-bootstrap`
- **Objective:** Implement the core harness commands in `scripts/harness/` (each file ≤ 250 lines) with unit tests.
- **Spec references:** §26 (all), §0.5, §0.6, §0.8, §0.11.
- **Behavior:**
  - `plan.ts m<N>`: extract the `#### M<N> work packages` table from `docs/spec.md` into `docs/orchestration/m<N>/plan.md` with a `Status` column (default `planned`); if the file exists, keep existing statuses and the "Changes from spec table" section and only add missing rows.
  - `brief.ts <WP-ID>`: render `harness/templates/brief.md` from the plan row (objective, write scope, acceptance, dependencies as inputs), spec references found in the objective, and **Known pitfalls** from every `harness/lessons/*.md` with `status: active` whose `affectedPaths` globs overlap the WP write scope; print to stdout, `--write` saves to `docs/orchestration/m<N>/briefs/<WP-ID>.md`.
  - `record.ts <WP-ID> --attempt <k> [--runner lead|worker] [--base <branch>]`: run the acceptance commands from the plan row (commands wrapped in backticks), `pnpm verify:fast`, and `pnpm check:scope <WP-ID>`; capture exit code, duration and up to 20 failing lines each; suggest classes via `harness/config.yaml` `gateClassMap`; write `harness/metrics/attempts/<WP-ID>-a<k>.json` validated against `harness/schemas/attempt.schema.json`; never overwrite another runner's file (lead file suffix `-lead`).
  - `retro.ts m<N>`: aggregate attempt files for the milestone; count confirmed (else suggested) classes; list severe classes (promote on first occurrence) and ordinary classes over thresholds (`ordinaryInMilestone`, `ordinaryCumulative`) without an active lesson; scaffold `harness/lessons/<id>.md` (front matter per lesson schema, id `L-<YYYYMMDD>-<WP-ID>-<6 hex of sha256(title)>`) and `harness/evals/<id>/{repro,fixed}/` plus `eval.json`; print first-pass rate, retries, takeovers and total gate duration per WP.
  - `evals.ts`: for every active lesson, run `repro` (must match `expectExitCode`, usually nonzero) and `fixed` (must be zero); also run `harness/selftest/` when present; exit 1 on any mismatch.
  - JSON schema validation: implement a small validator for the subset used by the four schemas (type, required, enum, pattern, minimum, items, additionalProperties, $ref to $defs) in `scripts/harness/lib/schema.ts` — no new dependencies.
  - YAML: `harness/config.yaml` uses only maps, lists, strings, integers and comments; parse with a minimal parser in `scripts/harness/lib/yaml.ts` — no new dependencies.
- **Write scope:** `scripts/harness/`; `scripts/test/harness/`
- **Inputs:** `harness/config.yaml`, `harness/schemas/*.json`, `harness/templates/*.md`, `docs/spec.md` §21.3 table format, `docs/orchestration/m0/plan.md`.
- **Acceptance:** `pnpm vitest run scripts/test/harness` passes; `pnpm harness:brief M0-W1` prints every brief field; `pnpm harness:plan m1 --dry-run` prints the M1 table with a Status column; schema validator rejects an attempt file missing `gates`.
- **Boundaries:** no changes to `harness/` data files (lead-owned), dependencies or lockfile; Node built-ins only; functions within §6.2 limits.
- **Report:** `docs/orchestration/m0/reports/M0-W3.md` with front matter per `harness/schemas/report.schema.json`.
