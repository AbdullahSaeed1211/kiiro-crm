# Report: M0-W3

Core harness commands are implemented in `scripts/harness/` with Node built-ins only: `plan`, `brief`, `record`, `retro` and `evals`, plus small libraries for the JSON-schema subset, the YAML subset, markdown tables, glob overlap, attempts, lessons, gates, git and lesson scaffolding. Every file is under 250 lines and passes the gated ESLint rules, strict tsc and Prettier. There are 60 unit tests, all of which use temporary repositories and injected command runners; one test uses a real `sh` runner.

Look at these first:

- **`record` and check:scope:** `record` treats a missing check:scope as unavailable (exit 127 plus a note), so it runs today, before M0-W1 merges. Its parsing of scope violations depends on the check:scope output format (see open questions).
- **Retro scaffolds block evals:** retro-scaffolded lessons are `active` with evals that fail on purpose. This keeps `pnpm harness:evals` red until the lead completes each lesson (§26.5, §26.8).
- **Plan merge rule:** `plan` never re-adds a row the lead removed and recorded under "Changes from spec table".
