# Report: M1-W5

`/timeline` renders dated tasks as SVAR Gantt bars (MIT edition). Dragging or resizing a bar persists `startAt` and `dueAt` through `setTaskDates`, and the change survives a reload. The code is commit b8ab33e on `wp/M1-W5`.

- The composite is `packages/ui/src/composites/GanttView/`. Its pure date, rollback and scale logic is in `model.ts`, covered by `model.test.ts`.
- Following the lead's scope change, `runSetTaskDates` lives in `apps/web/src/server/work/set-task-dates.ts`. The `'use server'` file exports only `setTaskDates`.
- Action tests cover success, VALIDATION (start after due, malformed input), FORBIDDEN (staff outside scope), NOT_FOUND and CONFLICT (stale `expectedUpdatedAt`).

Acceptance results:

- Pass: unit tests, typecheck, lint, format:check, depcruise, jscpd and `pnpm --filter web build`. The build lists `/timeline`.
- On `pnpm dev`, `/timeline` returned HTTP 200. The drag and conflict Playwright scripts passed every check.
- `pnpm harness:record M1-W5 --attempt 1` passed all five gates.
- `check:brand` and `knip` exit 1, but only on files outside this WP's scope.

Look at these first:

1. `check:scope` flags `set-task-dates.ts`, and `harness:record` suggests SCOPE_VIOLATION. The file was added by the lead's message; the plan row does not list it.
2. The MIT build strips `markers`, so the today marker is a highlighted day column and appears only in week zoom.
3. SVAR adds 80,538 B gzip of JS and 20,614 B gzip of CSS, and only `/timeline` loads them.
4. `css.d.ts` declares `*.css` for all of `@ops/ui`, because TypeScript 6 checks side-effect imports.
