# Report: M1-W10

The repository compare-and-set write is now a single conditional statement on D1, `UPDATE ... WHERE id = ? AND updated_at = ? RETURNING id`, issued through the adapter's own Drizzle instance with bound values. Commit 209d7fa on `wp/M1-W10`.

- **Integration tests:** 17 of 17 pass with no expected failures. The concurrent `saveDates` case passes as a normal test, and `saveStage` uses the same path.
- **Other gates:** `pnpm test`, `typecheck`, `lint`, `format:check`, `knip` and `harness:record` pass.

Look at these first:

1. The raw write skips Payload's field validation. The one practical effect is that a negative task date is now stored instead of refused (open question 1).
2. Update access is still checked with Payload's `executeAccess` against the expected version, just before the write.
3. E-017 needs updating to describe the new mechanism.
