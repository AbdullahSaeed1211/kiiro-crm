# Report: M1-W9

`pnpm db:reset:local` recreates the local D1 database from migrations. `pnpm seed:dev` idempotently upserts the development data subset through the Payload Local API. `GET /api/v1/health` returns `{ status, version, migration }`. On a fresh reset the first seed creates 1 settings, 2 groups, 4 users, 2 workflows, 1 organization, 2 projects and 12 tasks; the second creates nothing. On `pnpm dev`, health returns 200 with `20260913_131654_initial` and the seeded owner can log in.

Look at these first:

1. Payload's development schema push adds a `dev` row with batch −1 to `payload_migrations`, so the health route skips batch −1 and sorts by batch and name, not `createdAt`.
2. The scripts load Payload and the web config dynamically from `apps/web`, because the repository root cannot resolve them.
3. `pnpm dev` needs `PAYLOAD_SECRET` in the environment; this worktree has no `.env`.
