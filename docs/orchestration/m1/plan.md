## Notes

### M1-L2 transaction probe (D-36 input)
Run on 2026-09-13 against local D1 (`getPlatformProxy`, isolated persistence directory, one `probes` collection pushed by `@payloadcms/db-d1-sqlite@3.89.0`): `initTransaction`, two `payload.create` calls on the same request, then `killTransaction` and a count.
- Default adapter options: `{"began":false,"rowsAfterRollback":2}`. The adapter uses Payload's no-op `defaultBeginTransaction`, so writes are never atomic and a rollback undoes nothing.
- With `transactionOptions: {}`: `{"beginError":"cannot begin transaction: Failed query: begin","writeError":"cannot begin transaction: Failed query: begin","rowsAfterRollback":0}`. D1 rejects `BEGIN`, so interactive transactions are unavailable.
- Consequence for D-36 (decided in M1-L3 after the deployed check): ordered writes guarded by conditional updates (`expectedUpdatedAt`) and idempotency keys; `createUnitOfWork` already degrades to ordered writes when no transaction starts.
