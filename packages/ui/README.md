# @ops/ui

## Purpose

shadcn/ui primitives (Base UI, `base-nova` style, neutral base color) and brand-agnostic composites. No data fetching; every string arrives translated from the app.

## Public API

- `ThemeProvider`: light, dark and system themes (D-19).
- Root exports and `@ops/ui/composites/<name>` expose `StagePill`, `StageSelect`, `RecordPageLayout`, `ActivityFeed`, `ConfirmDialog`, `RecordForm`, and `FilterBar`. These composites remain data-source agnostic and receive labels and records from the app.
- `@ops/ui/globals.css`: Tailwind 4 entry with the shadcn neutral theme and the product tokens from `src/styles/tokens.css` (success, warning, info, stage colors; spec §15.2).
- `@ops/ui/components/ui/<name>`: vendored shadcn components (spec §15.1), added with `pnpm dlx shadcn@4.21.0 add <names> -c apps/web`.
- `@ops/ui/lib/utils`: `cn` class merging.

## Vendored components

`src/components/ui/` and `src/hooks/use-mobile.ts` are generated by the shadcn CLI and excluded from formatting, lint gates, duplication and dead-code checks. The CLI placed `use-mobile.ts` in the app's hooks folder; it was moved to `src/hooks/`, where `sidebar.tsx` imports it. The `shadcn` package is a runtime dependency only because `globals.css` imports `shadcn/tailwind.css`; it is not bundled into the Worker.

Modifications to vendored files, all required by the strict compiler options in `tooling/tsconfig/base.json` (re-apply after any `shadcn add --overwrite`):

- `calendar.tsx`: `CalendarDayButton` accepts `locale?: Partial<Locale> | undefined` (`exactOptionalPropertyTypes`); `modifiers` flags are read with bracket access (`noPropertyAccessFromIndexSignature`).
- `sonner.tsx`: the theme cast is `NonNullable<ToasterProps["theme"]>` (`exactOptionalPropertyTypes`).
