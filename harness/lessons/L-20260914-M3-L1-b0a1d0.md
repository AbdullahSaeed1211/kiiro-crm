# Task board moves must use the persisted transition shape

Dragging a task between workflow stages must update the task and write a valid stage-transition record.

## Symptom

The board move endpoint updated the task payload but rejected the transition row with invalid `Record Type`, `Record Id`, and `Workflow` fields. The board then showed a failure toast and the move was not durable.

## Cause

The domain command represents a transition with a nested `record` reference and `workflowId`, while the Payload collection stores those values as top-level `recordType`, `recordId`, and `workflow` fields. The task repository passed the domain object directly to Payload.

## Countermeasure

The repository now maps the domain transition to the Payload field shape before creating the system row. The smoke suite exercises a real task drag and verifies the card remains in its destination stage after the response.

## Eval

`harness/evals/L-20260914-M3-L1-b0a1d0/eval.json` reproduces the nested domain payload and passes the flattened Payload payload.
