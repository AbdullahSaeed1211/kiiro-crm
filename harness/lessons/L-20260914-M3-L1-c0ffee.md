# Customer authentication must stay on the product surface

The customer UI uses `/login` for sign-in and protected route redirects, while the administrative Payload panel remains private and absent from customer navigation.

## Symptom

The existing end-to-end smoke suite signed in through the administrative login and the work repository still redirected unauthenticated users there. That allowed a customer-facing auth regression to pass unnoticed.

## Cause

The product login route existed, but the smoke fixture and one shared work context retained the historical admin boundary. The visual shell also had no assertion that customer navigation excluded administrative links.

## Countermeasure

The smoke suite signs in through `/login`, asserts the product shell, verifies protected redirects and checks that customer navigation contains no `/admin` links. The fixture eval keeps the boundary executable without requiring a live browser.

## Eval

`harness/evals/L-20260914-M3-L1-c0ffee/eval.json` reproduces the stale admin boundary and passes the corrected `/login` surface.
