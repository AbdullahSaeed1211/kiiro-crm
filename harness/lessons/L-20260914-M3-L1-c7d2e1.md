# GATE_FAILURE in M3-L1

Aggregate gate failures must be recorded before remediation. The record must enumerate every failed gate and preserve its output so the next append-only attempt can be compared with the failed state.

## Symptom

The lead made successive remediation attempts after aggregate verification failures. Without an explicit aggregate record, a later green subset of gates could obscure which failure remained open.

## Cause

Leaf test results and individual gate results were available, but the completion review did not make the complete failed-gate set and its ordering relative to remediation a separately executable requirement.

## Countermeasure

The completion report names the aggregate gate result, and each remediation follows an attempt that records all failed gates and their output. Earlier attempts and worker reports remain append-only. The eval rejects a record that omits one failed gate and accepts a record that covers every failed gate before remediation.

## Eval

`harness/evals/L-20260914-M3-L1-c7d2e1/eval.json`: `repro/` must fail because one failed gate is absent from the pre-remediation record; `fixed/` must pass after all failed gates are recorded.
