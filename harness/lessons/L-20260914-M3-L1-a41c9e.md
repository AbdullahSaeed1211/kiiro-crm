# GATE_FAILURE in M3-L1

A vertical may report DONE only when every acceptance-owned output exists, and aggregate gate failures must be recorded before remediation. Leaf tests do not prove that routes, persistence, user interfaces and Worker entry points were delivered.

## Symptom

The intake and mail worker reported a complete vertical, but the public intake route, intake persistence, settings screens and executable mail-router entry were absent. A later aggregate review also required an explicit record of every failed gate before remediation.

## Cause

The completion review trusted passing leaf tests and the report status without checking the claimed deliverables against the work package acceptance surface. It also did not make the complete aggregate failed-gate set and its output an explicit pre-remediation requirement.

## Countermeasure

Completion review must list the acceptance-owned paths and verify that each required output exists before a DONE report is accepted. When an aggregate gate fails, the attempt must record every failed gate and its output before remediation begins. The executable evals reproduce an incomplete DONE claim and an incomplete aggregate record, then accept the fixed forms.
