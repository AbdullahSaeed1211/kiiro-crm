# ACCESS_SCOPE in M2-W6, M2-W7

M2 CRM reads and mutations must preserve staff scope while allowing owner and manager access where the contract permits it. Authorize the parent record before elevating related reads.

## Symptom

Review found that staff scope and parent authorization had to be carried through deal, organization, contact and activity reads. Source attempts: M2-W6-a4, M2-W7-a5, M2-W7-a6.

## Cause

A query or related activity read can bypass the actor's owner, assignee, group or report scope when it uses an unrestricted read before the parent record is authorized.

## Countermeasure

Keep scope predicates in the platform policy and pass the authenticated request through CRM repository and related reads. Focused permission and directory tests assert that staff see only in-scope records, while parent-authorized related reads are the only elevated reads. The eval rejects a leaked record and accepts the scoped result.
