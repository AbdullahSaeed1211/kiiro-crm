# Confirmed tenant data must be prefilled end to end

Tenant-specific values must flow from the confirmed manifest into persisted settings, seed data, onboarding, and settings forms. Placeholder owner, timezone, currency, host, or email values are a failed integration even when routes render.

## Symptom

The shell was branded, but settings and onboarding still showed placeholder regional and owner data. A user had to re-enter known customer details before the workspace was usable.

## Countermeasure

Keep the manifest and seed as the single prefill authority, migrate legacy local owner data idempotently, and run the executable evidence eval before acceptance.
